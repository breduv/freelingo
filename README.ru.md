## Обзор

FreeLingo — платформа для изучения языков с открытым исходным кодом, структурированной программой
A1–C2 и ИИ-преподавателем **Lingu**. Можно пользоваться облачным сервисом или развернуть приложение
на собственной инфраструктуре.

Этот форк [artcc/freelingo](https://github.com/artcc/freelingo) добавляет настройки ИИ через браузер,
локальный вход через ChatGPT. Описанный ниже облачный сервис — отдельная установка команды оригинала.

1. **Определите начальный уровень.** Пройдите адаптивный тест или начните с A1, если изучаете язык
   с нуля. Проверка теста и составление расписания детерминированы: план учитывает программу
   выбранного языка, уровень и продолжительность — 4, 8, 12 или 16 недель.
2. **Следуйте плану.** Проходите разделы программы с понятными компетенциями и требованиями
   к предыдущим знаниям. ИИ создаёт материал уроков в этих рамках, с объяснениями на родном языке
   и заданиями по грамматике, лексике, пониманию текста и письму.
3. **Практикуйтесь с Lingu.** Общайтесь текстом и голосом, управляя тем, что преподаватель помнит
   о вас. После завершённых уроков доступна голосовая практика: подтвердите предложенную тему
   и обсудите материал с учётом ваших ответов на задания. Для этих разговоров действуют обычные
   голосовые лимиты; они сохраняются в истории чата под темой урока.

В дополнение к плану:

- **Повторение и самостоятельное изучение:** карточки с алгоритмом SM-2, материалы по грамматике
  и лексике, разговорник, генерируемые задания Listening и Reading, практика произношения.
- **Обучающие игры:** [Error Detective, Sentence Order и Vocabulary Pairs](specs/games.instructions.md).
  Повторяйте завершённые уроки, закрепляйте знакомые основы перед следующим уроком или занимайтесь
  на уровне своего плана. Сессии сохраняются, история разделяется по языкам, а XP относится
  к соответствующему плану. Для бесплатного доступа действует общая дневная квота игр.
- **Отслеживание прогресса:** XP, серии занятий, оценки навыков, компетенции по разделам
  и итоговые тесты уровня. На главном экране показаны XP за сегодня, активность за семь дней
  и продвижение по плану. Награды учитывают уроки, повторение, содержательное общение с преподавателем
  и завершение разделов и уровней; для активности используются даты UTC.
- **Несколько языков одновременно:** отдельные планы, прогресс, карточки и попытки выполнения
  заданий для каждого изучаемого языка. Настройки аккаунта, подписка, квоты и память преподавателя
  остаются общими.

## Архитектура

Монорепозиторий объединяет **frontend на Next.js** и **backend на FastAPI**; развёртывание
выполняется через Docker Compose.

- **Frontend:** отображение интерфейса, навигация, запись и воспроизведение звука в браузере.
- **Backend:** бизнес-логика, аутентификация, сохранение данных и все интеграции LLM, TTS и STT.
- **Хранилища:** PostgreSQL 16 для постоянных данных приложения; Redis 7 для сессий и служебного
  состояния.

Frontend не обращается к провайдерам ИИ и речевых сервисов напрямую.

Структура системы описана в [спецификации архитектуры](specs/architecture.instructions.md),
а окружение запуска и образы — в [спецификации Docker](specs/docker.instructions.md).

## Стек

- **Frontend:** Next.js 16, shadcn/ui, Tailwind CSS, Zustand, next-intl
- **Backend:** FastAPI, асинхронный SQLAlchemy, Alembic, Pydantic v2
- **Данные:** PostgreSQL 16 и Redis 7
- **LLM:** исходные подключения Ollama, OpenAI, Anthropic и DeepSeek, а также локальный вход через ChatGPT
- **Речь:** Kokoro-FastAPI или OpenAI TTS; faster-whisper или OpenAI Whisper
- **Аутентификация:** JWT-токены доступа и refresh-токены, роли admin/user
- **Развёртывание:** Docker Compose

## Быстрый старт

Выберите **[Docker Compose](#вариант-a--git-clone--docker-compose)** для развёртывания из командной
строки или **[Portainer](#вариант-b--portainer-stack)** для управления стеком.

**Требования к серверу**

- Docker и Docker Compose 2.24.4+ для локального overlay; Git при клонировании репозитория.
- Реквизиты OpenAI, Anthropic или DeepSeek либо [Ollama](https://ollama.com); также доступен локальный вход через ChatGPT.
- NVIDIA GPU для стандартных локальных речевых контейнеров либо ключ OpenAI API для облачной речи.
- Для голосового общения в продакшене: HTTPS и маршрутизация `/ws/*` через обратный прокси,
  как описано [ниже](#требования-к-обратному-прокси-голосовое-общение).

До запуска выберите [речевые провайдеры](#настройка-tts-и-stt). Стандартный Compose включает
GPU-контейнеры обоих локальных речевых сервисов; выбор OpenAI в `.env` сам по себе их не отключает.

### Вариант A — Git clone + Docker Compose

**1. Клонирование и настройка**

```bash
git clone https://github.com/breduv/freelingo.git
cd freelingo
cp .env.example .env
```

В `.env` задайте реквизиты БД и Redis, `SECRET_KEY`, провайдеров LLM и речи.
Локальный overlay использует именованные тома; оставьте `DATA_PATH` со значением из шаблона.
Остальные настройки описаны в [.env.example](.env.example).

**2. Подготовка модели — только для Ollama**

На компьютере с Ollama выполните:

```bash
ollama pull gemma4:e4b
```

**3. Запуск стека**

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build
```

Compose также собирает расширенный образ Kokoro. При первом запуске он скачивает закреплённые
модели и данные русского произношения в том `kokoro-models`; это может занять несколько минут.
Сервис становится healthy после загрузки моделей. Вручную устанавливать пакеты, копировать
модели или запускать PowerShell-скрипт не нужно. Следующие запуски используют сохранённый том.

При каждом запуске backend автоматически применяются ожидающие миграции БД.
Отдельный `Dockerfile.local` загружает зафиксированный исходник оригинала и накладывает перечисленные
локальные файлы. Backend использует закреплённый upstream runtime, frontend пересобирается с панелью.
Образы остаются локальными; публикация в реестр не требуется. Workflow оригинала не изменены;
оставьте GitHub Actions выключенным в форке, если автоматическая публикация образов и релизов не нужна.
Шлюз доступен через loopback.
Откройте `http://localhost:3000`. На Windows скрипты `start.ps1` и `stop.ps1` используют тот же overlay.
Docker должен быть уже доступен; выбранную локальную LLM нужно запустить отдельно. Запуск контейнеров
не гарантирует, что загрузка речевых моделей завершена. Данные и настройки ИИ хранятся в постоянных
томах отдельного Compose-проекта `freelingo-fork` и сохраняются после остановки.
Для доступа к микрофону в продакшене требуется описанная ниже настройка HTTPS.

По умолчанию первый зарегистрированный пользователь становится администратором. Чтобы отключить
это поведение, задайте `FIRST_USER_IS_ADMIN=false`.

### Вариант B — Portainer (Stack)

1. Откройте Portainer → **Stacks** → **Add stack**.
2. Выберите **Repository** и укажите URL репозитория либо вставьте содержимое `docker-compose.yml`
   непосредственно в Web editor.
3. Добавьте переменные из `.env.example`: как минимум `DATA_PATH`, значения `POSTGRES_*`,
   `REDIS_PASSWORD`, `SECRET_KEY`, выбранных провайдеров LLM и речи и их реквизиты.
4. Нажмите **Deploy the stack**.
5. Откройте `http://<server-ip>:3000`. Миграции БД применяются автоматически при запуске backend.

Этот вариант с обычным Compose использует оригинальные upstream-образы без локальных изменений.
Для панели ИИ и ChatGPT используйте вариант A. Удалённый Portainer не предоставляет
локальный callback браузера для входа в ChatGPT автоматически.

> **Ollama на том же хосте:** задайте `OLLAMA_BASE_URL=http://host.docker.internal:11434`.
> На Linux, если это имя ещё не разрешается, добавьте `host.docker.internal:host-gateway`
> в `extra_hosts` сервиса backend. В продакшен-Compose эта запись отсутствует.

## Эксплуатационные замечания

### Провайдеры ИИ

- **Языковая модель:** `LLM_PROVIDER` выбирает `ollama`, `openai`, `anthropic`, `deepseek` или `chatgpt`.
  Рекомендуемая модель Ollama — `gemma4:e4b`; другую можно выбрать через `.env`.
- **Настройки через браузер:** войдите как администратор и откройте **Настройки → Настройки ИИ**.
  Получите список моделей и проверьте новые параметры до сохранения. Сохранённые параметры имеют
  приоритет над `.env` для новых операций и применяются без перезапуска. Ключи зашифрованы
  на backend и не возвращаются на страницу.
- **ChatGPT:** выберите ChatGPT в этой панели, подключите аккаунт, загрузите модели, проверьте
  ответ и сохраните настройки. Доступность и лимиты зависят от OpenAI и плана аккаунта. Один аккаунт
  используется всей локальной установкой, без автоматического перехода на платный API.
  Речевые сервисы остаются отдельными.
- **Речь:** `TTS_PROVIDER` и `STT_PROVIDER` независимы. Каждый выбирает `local`
  (Kokoro / faster-whisper) или `openai`. См. [настройку речи](#настройка-tts-и-stt).

<details>
<summary><strong>Настройки провайдеров</strong></summary>

- Запросы к OpenAI используют **Responses API**, в `.env.example` задано `OPENAI_MODEL=gpt-6-luna`.
  Выбранные модель и endpoint должны поддерживать Responses; шлюза только с Chat Completions
  недостаточно. FreeLingo управляет контекстом разговора и отправляет `store=false`.
- Необязательный `OPENAI_REASONING_EFFORT` применяется к чату OpenAI, инструментам памяти и генерации.
  Пустое значение оставляет выбор модели. Доступны `none`, `minimal`, `low`, `medium`, `high`, `xhigh`
  и `max` с учётом поддержки моделью; специальных переопределений по имени модели нет.
- Ollama и DeepSeek используют Chat Completions, Anthropic — свой нативный API.
- `ANTHROPIC_MAX_TOKENS` по умолчанию равен `8192` и должен соответствовать лимиту выбранной модели.
- В панели выбираются провайдер, его модель и ключ. Адрес сервера настраивается только для Ollama.
  Таймаут, лимит ответа, temperature, рассуждения и инструменты обрабатывает адаптер выбранного провайдера.
- Промпты ИИ, генерация и схемы уроков соответствуют закреплённой версии оригинала. Объяснение,
  словарь и задания создаются вместе; дополнительной проверки, введённой в форке, нет.
- Сохраняйте резервную копию зашифрованных настроек ИИ вместе с `SECRET_KEY`. Потеря или смена секрета
  не позволит расшифровать их. Авторизация ChatGPT использует точный HTTP loopback callback
  на `127.0.0.1`; см. [официальный протокол входа](https://developers.openai.com/siwc/token-sharing-open-source/sign-in).
- Подключение ChatGPT остаётся привязанным к проверенному аккаунту после отключения. Выбор другого
  аккаунта пока не предусмотрен в панели; повторный вход должен использовать исходную учётную запись.

Поведение провайдеров описано в [контрактах сервисов](specs/services.instructions.md).

</details>

### Лимиты и доступ

Лимиты разговоров, токенов, бесплатного доступа и пробного периода настраиваются
в [.env.example](.env.example). Для квот на число сессий, минуты и токены `0` означает отсутствие
ограничения; для квот бесплатных функций `0` блокирует функцию. Продолжительность разговора
и таймаут бездействия имеют собственные границы.
См. [подписки и квоты](specs/subscriptions-freemium.instructions.md).

Веб-подписки используют Stripe Checkout. Необязательный `REVENUECAT_ENABLED=true` синхронизирует
общий доступ Premium через RevenueCat, сохраняя платежи Stripe и существующий веб-интерфейс.
Нужны `STRIPE_ENABLED=true`, реквизиты провайдера, настройка webhook и импорт существующих подписок
до включения. См. [настройку и эксплуатацию RevenueCat](specs/subscriptions-freemium.instructions.md#revenuecat-configuration-and-operation)
и [.env.example](.env.example).

### Изучаемые языки

Изучайте один язык или несколько параллельно. Для каждого есть программа A1–C2, тест уровня,
грамматический справочник, словарь и разговорник.

- **Китайский:** путунхуа материкового Китая, упрощённые иероглифы (`zh-CN`).
- **Нидерландский:** Нидерланды (`nl-NL`).
- **Английский:** британский (`en-GB`) и американский (`en-US`).
- **Французский** (`fr-FR`).
- **Немецкий** (`de-DE`).
- **Итальянский** (`it-IT`).
- **Японский** (`ja-JP`).
- **Корейский:** Южная Корея (`ko-KR`).
- **Польский** (`pl-PL`).
- **Португальский:** бразильский (`pt-BR`) и европейский (`pt-PT`).
- **Русский** (`ru-RU`).
- **Испанский:** Испания (`es-ES`).
- **Шведский:** Швеция (`sv-SE`).

Первый язык выбирается при начальной настройке. Затем можно добавлять языки через
**Настройки → Мои языки**. Планы, прогресс и карточки разделены по языкам, включая региональные
варианты. В самостоятельной установке доступные варианты задаёт `AVAILABLE_TARGET_LANGUAGES`.

Родной язык выбирается отдельно при регистрации. Он используется для переводов, объяснений
и обратной связи преподавателя, помогающих учиться.

## Хост Linux: memory overcommit для Redis

Для надёжного фонового сохранения Redis (RDB-снимки) на хосте нужен `vm.overcommit_memory=1`.
Без него `fork()` при нехватке памяти может завершиться ошибкой, а несохранённые данные — потеряться
после перезапуска.

Один раз выполните на сервере:

```bash
sudo sysctl vm.overcommit_memory=1
echo "vm.overcommit_memory = 1" | sudo tee -a /etc/sysctl.conf
```

Первая команда применяет настройку сразу, вторая сохраняет её после перезагрузки. Это настройка
хоста; применить её из контейнера без повышенных привилегий нельзя.

## Требования к обратному прокси (голосовое общение)

> [!IMPORTANT]
> Для голосового общения в продакшене нужны **HTTPS** для доступа к микрофону и **маршрутизация
> WebSocket** на backend. HTTP rewrites Next.js не передают WebSocket upgrade.

Направляйте `/ws/*` на `backend:8000`, включая `/ws/conversation`. Продакшен-frontend определяет
WebSocket URL из `window.location`.

Для доступа к микрофону браузеру нужен [безопасный контекст](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts),
например HTTPS или localhost. Обычный HTTP по IP-адресу сервера таким контекстом не является.

## Настройка TTS и STT

TTS и STT — обязательные сервисы. Для каждого независимо выбирается один из двух провайдеров в `.env`.

- `TTS_PROVIDER=local` использует Kokoro-FastAPI; `TTS_PROVIDER=openai` — OpenAI TTS.
- `STT_PROVIDER=local` использует faster-whisper; `STT_PROVIDER=openai` — OpenAI Whisper.
- Если хотя бы один сервис использует OpenAI, нужен `OPENAI_API_KEY`.

### Локальная речь

Стандартные локальные сервисы в `docker-compose.yml` настроены для NVIDIA GPU:

```env
TTS_PROVIDER=local
STT_PROVIDER=local
```

Локальный overlay расширяет Kokoro [русской](https://huggingface.co/zaakirio/kokoro-ru) и
[немецкой](https://huggingface.co/kikiri-tts/kikiri-german-martin) моделями. Голоса выбираются из
`deploy/kokoro/voices.json`: британский английский — Emma, американский — Heart, русский — Маша,
немецкий — Martin. Для русского также доступна Света. Исходные языки Kokoro сохраняются.
Модели сохраняют опубликованные авторами лицензии; русские веса распространяются по OpenRAIL.

Соответствия языка и голоса можно менять в этом файле без пересборки и перезапуска сервисов.
Compose подключает один файл в backend и Kokoro; его содержимое входит в ключи кеша озвучки тура
и разговорника. Смешанный текст произносится в исходном порядке, без перевода. Смена письменности
определяется напрямую, смена языков с латиницей — локальным классификатором; короткие неоднозначные
фрагменты определяются приблизительно. При смене языка может меняться диктор. Для португальского
используется бразильская модель. Польский, нидерландский, шведский, корейский и озвучка тура на
румынском/хорватском локально не поддерживаются.

Расширение работает в локальном overlay; обычный Compose сохраняет upstream Kokoro.
OpenAI TTS остаётся доступен; подробности — в [речевой спецификации](specs/speech-services.instructions.md).

Для локального развёртывания только на CPU задайте `KOKORO_DEVICE=cpu` в сервисе Kokoro,
удалите резервирование GPU и выберите CPU-образ Whisper с меньшей моделью, как описано
в [спецификации Docker](specs/docker.instructions.md).

### Облачная речь

Для провайдеров OpenAI не нужны локальный GPU и речевые контейнеры:

```env
TTS_PROVIDER=openai
STT_PROVIDER=openai
OPENAI_API_KEY=sk-...
```

Удалите соответствующие блоки `kokoro` и/или `whisper` из Compose-файла развёртывания, если эти
сервисы используют OpenAI. Смена переменных провайдера сама по себе не удаляет резервирование GPU.

Переменная `OPENAI_API_KEY` задаёт начальный ключ OpenAI для LLM и речи. Ключ, сохранённый в панели
LLM, не меняет реквизиты речевых сервисов. Доступные настройки описаны
в [.env.example](.env.example), контракты провайдеров — в [спецификации речевых сервисов](specs/speech-services.instructions.md).
